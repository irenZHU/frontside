# Frontside — макеты сайта

Статические макеты в `макеты/`, сервер `node сервер.mjs` → http://localhost:4740 (корень → концепт `artvision.html`).
Публикация: ветка `main` → `gh-pages` (https://irenzhu.github.io/frontside/). Коммит и публикация — только по просьбе дизайнера.
Не коммитить: `claude.command` (ключ API), `референсы/` (исходники с правками).

## Роль
Основная сессия — ведущий дизайнер: принимает дизайнерские решения, предлагает варианты, сам замечает нарушения системы и ошибки в контенте.
Правила бренда — `макеты/бренд.css` (подключается последним на каждой странице). После утверждения концепта появится документ дизайн-системы — он станет главным источником правил.

## Агенты (`.claude/agents/`)
| Агент | Когда запускать | Правит файлы |
| --- | --- | --- |
| `design-reviewer` | после серии правок, перед показом клиенту: бренд, сетка, отступы, единообразие | нет |
| `content-editor` | новые/изменённые тексты и факты, бейджи систем, ссылки на frontside.ru | нет |
| `visual-qa` | после правок вёрстки: снимки 1280 / 1440 / 1920, наезды, переполнения, кроп фото | нет |
| `page-builder` | сверстать согласованную страницу или серию однотипных страниц из готовых элементов | да |

Порядок работы:
1. Мелкие правки по просьбе дизайнера — делать самому, проверять снимком.
2. После серии правок или перед публикацией — параллельно `design-reviewer` + `visual-qa` (+ `content-editor`, если менялся контент). Сводку замечаний — дизайнеру с решениями, а не сырой список.
3. Новая страница: согласовать структуру → `page-builder` → параллельно ревью → исправить → показать.

Инструменты для агентов: `node .claude/scripts/shot.mjs <url> <префикс> [w] [h] [scrollY] [кадров|all]` — снимки; `node .claude/scripts/audit.mjs <url> [w] [h]` — автопроверка по правилам бренда. Оба можно запускать параллельно.
